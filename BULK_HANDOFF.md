## 1. Что это за проект

«Бульк» - уютная игра-кликер про волшебную лавку зелий [подтверждено перепиской]:
- игрок тапает по котлу с лицом;
- покупает карточки, которые приносят доход в час, в том числе пока игрок не в игре;
- выполняет заказы жителей, ежедневные задания, рецепт и руну дня;
- заводит питомцев и отправляет их в походы, выращивает яйца;
- меняет гардероб котла;
- участвует в топах и ковенах (кланах).

Платформы - мини-приложение ВКонтакте и Telegram Mini App, один общий мир с общим прогрессом. Игра только мобильная, десктопа нет, и кода под десктоп быть не должно.

- Сайт игры: https://vitalya2078-cloud.github.io/bulk/ (GitHub Pages, репозиторий `vitalya2078-cloud/bulk`, ветка `main`).
- Telegram: бот `@bulkgamemagikbot`, Main App.
- ВКонтакте: приложение с ID `54828995` (https://vk.com/app54828995). Приложение «непроверенное», то есть модерацию ВК ещё не проходило [подтверждено перепиской на 17.10].
- Владелец - Виталя. Работает только с телефона (Android), без компьютера: всё, что нужно сделать руками, он делает в мобильном браузере.

## 3. Стек, архитектура, файлы

Всё ниже - [проверено в сессии] по дереву файлов на момент составления. Перед правками сверьте с текущим репозиторием [проверить в репозитории].

**Стек.** Чистые HTML, CSS и JavaScript с canvas. Ни сборщика, ни npm-зависимостей нет. Скрипты подключаются тегами `<script>` в `index.html` в строгом порядке, модули - это глобальные константы (IIFE), например `const UI = (() => {...})()`.

**Сервер** - Supabase: Postgres и RPC-функции, URL `https://ahqaficklfciahzlghec.supabase.co`. Клиент вызывает `POST /rest/v1/rpc/<функция>` с publishable-ключом из `js/tops.js` (`CONFIG.tops`). Все таблицы закрыты RLS, доступ к ним `anon` и `authenticated` отозван. Вся работа идёт через функции `SECURITY DEFINER`, каждая проверяет подпись платформы.

**Корень репозитория:**
- `index.html` - игра; порядок `<script>` важен;
- `sw.js` - Service Worker: код берётся из сети первым, картинки из кэша по версии;
- `version.json` - номер версии для самообновления;
- `privacy.html` и `terms.html` - правовые документы, на них ссылается ВК;
- `README.md` - устарел.

**`css/style.css`** - все стили игры, разделы помечены версиями.

## 5. Решения и требования

Все пункты [подтверждено перепиской].

**Устройство игры**
- **Один мир ВК+Telegram** (вариант «Б»): общий прогресс, связка аккаунтов кодом, одновременно на двух устройствах играть нельзя.
- **Только мобильная версия.** Десктоп не нужен, кода под десктоп нет; в настройках ВК десктопная площадка не используется.
- **Ковены нужны к выходу во ВК.** Личные сообщения отложены.
- **Монетизация:** реклама за награду (только ВК) и покупки в будущем. В Telegram рекламы пока нет, покупок за голоса нет.
- **Самообновление.** Игра и приложение админки проверяют обновление при запуске, а игра ещё и при возвращении из фона. Новая версия загружается сразу, без переустановки.

**Оформление и тексты**
- **Админка** в своём минималистичном технологичном стиле, не игровом. Отдельный APK, вход по коду из игры. Кнопка с кодом видна только команде.
- **Тексты и цифры - в коде, всё остальное - картинками.** Новую графику пользователь генерирует сам по промтам от Claude.
- **Промты для картинок:**
  - готовы к копированию, 4K;
  - фон сплошной голубой `#00FFFF`, чтобы его можно было вырезать;
  - в конце строка «The attached image is ONLY a style reference - do not paste or copy it, draw a completely new image in the same style.»
  - Для обложек и сцен фон рисуется целиком, а надписи на русском пишутся прямо в промте.
- **Нигде нет полос прокрутки.** Окна топов, почты и ковенов одной высоты.
- **Никаких длинных тире** в текстах, коде и игре - только обычный дефис «-».
- **«Что нового»** показывается после обновления и по нажатию на строку версии. Тексты простые, для игроков.
- **«Назад» идёт по шагам.** В мини-играх кнопка показывает то же предупреждение, что и крестик.

**Работа с пользователем**
- Задавать уточняющие вопросы, когда в программировании есть выбор.
- Архивы называть простыми именами.
- Найденные ошибки записывать в `claude/bulk_bugs.md` в проекте claude.ai, а исправлять пачкой после команды пользователя.
- Общаться на «ты».

## 6. Данные, API, интеграции

**Аутентификация.** Функция `_tg_user(init_data)` проверяет:
- `initData` Telegram: HMAC, ключ = HMAC("WebAppData", токен бота);
- или `"vk:" + параметры запуска`: подпись `sign` = base64url(HMAC-SHA256) по отсортированным параметрам `vk_*`, ключ - защищённый ключ ВК.

Возвращает json, где `id` - uid игрока.

**Номер игрока (uid).** Он хранится в `players.tg_id`: у Telegram-игрока это его tg id, у ВК-игрока без связки - минус его vk id. Колонки `tg` и `vk` хранят id на самих платформах.

`_who(init_data)` (из `update7`) дополнительно принимает `"adm:" + ключ` приложения админки и проверяет его по таблице `adm_sessions`, где ключ хранится только как sha256. Через `_who` работают только `_can` и `adm_me`. Игровые функции ключ приложения не принимают.

**Секреты** лежат в таблице `private_secrets`, имена ключей `tg_bot_token`, `vk_secret`, `vk_service`. Пользователь вставляет их сам через SQL Editor, значения в репозитории не хранятся. Наличие в базе:
- `tg_bot_token` - есть [подтверждено перепиской];
- `vk_secret` - [предположение]: вход через ВК работает, значит ключ вставлен;
- `vk_service` - есть [подтверждено перепиской 23.10].

**Миграции.** В репозитории файлы с `setup` по `update9` [проверено в сессии]. Что из этого реально выполнено на боевой базе:

## 9. Ошибки, долг и риски

**Ошибки и непроверенное поведение**
- **Мост к ВК.** Протокол `miniBridge` написан по памяти и проверен только на заглушке. Если оба CDN недоступны, а протокол неточен, во ВК могут не работать сохранение в облако ВК и реклама. Сам запуск это не ломает: `VKWebAppInit` отправляется отдельно.
- **Защита топов эвристическая.** Ложные срабатывания возможны, порог задан с запасом. Подозрительный игрок не банится, а уходит в `top_hold` и вкладку «Проверка» в админке.
- **Перебор кода входа.** Ограничение на перебор кода приложения админки общее для всех: 20 ошибок за 10 минут. Злоумышленник может временно заблокировать вход всей команде.

**Безопасность**
- **Ключ подписи APK** `android/admin.jks` и его пароль лежат в публичном репозитории. Пользователь знает об этом. Без кода из игры приложение ничего не открывает.
- **Защита на старых версиях.** В `hello` до `update8` цифры прогресса принимались без проверки. Если `update8` не выполнен, защиты топов нет.

**Технический долг**
- **`README.md`** описывает версию 0.4.0.
- **vk-bridge грузится с CDN** по `@2` без точной версии: скачать пакет в контейнер Claude не удалось.
- **Сборка.** `tools/build.py` раньше жил только во временной папке Claude и в репозитории его не было, это исправлено этим коммитом. Тестовый стенд в репозиторий не попал: локальный Postgres и скрипты `pgrest.py`, `*test*.py`.
- **В `js/manifest.js`** `files` на одной длинной строке: его генерирует `tools/build.py`, руками не править.

**Риск при каждом выпуске.** Если `version.json` и `index.html` разойдутся по версии, у игроков будет одна лишняя перезагрузка за сеанс. Защита от петли перезагрузок есть: метка в `sessionStorage`.

## 10. Сборка, запуск, проверки, деплой

**Сборка** [проверено в сессии]: `python3 tools/build.py .`, запускать из корня репозитория. Скрипт:
- берёт версию из `js/config.js`;
- пишет `js/manifest.js` и `version.json`;
- переписывает `?v=` у всех ссылок в `index.html`;
- пишет `admin/bundle.json` с отпечатками файлов админки.

Ленивые папки, которые не грузятся на заставке, перечислены в списке `LAZY` внутри `build.py`. Новые файлы `js/*.js` нужно вписывать в `index.html` руками в правильное место.

**Выпуск версии:**
1. Поднять `version` в `js/config.js`.
2. Добавить запись в `CHANGES` в `js/changelog.js`, если есть что сказать игрокам.
3. Запустить `tools/build.py`.
4. Сделать коммит и пуш в `main`. GitHub Pages выкладывает сам.
5. Игроки получат обновление через `Updater`.

**Коммиты** делались с `-c user.name="vitalya2078-cloud" -c user.email="vitalya2078@gmail.com"`. В конце сообщения - строки `Co-Authored-By` и `Claude-Session`.

**SQL.** Новые миграции - новым файлом `supabase/updateN.sql`. Файл должен быть безопасен для повторного запуска: `create or replace`, `if not exists`. Пользователь выполняет его сам в SQL Editor Supabase с телефона, по ссылке `raw.githubusercontent.com/.../supabase/updateN.sql`. Ссылку давать целиком.

**APK админки** собирается в Actions только при изменении `android/**`. Сама админка в APK обновляется через `admin/bundle.json` без пересборки.

**Тесты.** Автотестов в репозитории нет. В сессии игру проверяли Playwright-ом (Chromium) с подменой Supabase на локальный Postgres 16 и подписями Telegram и ВК, сделанными тестовыми ключами. Сами скрипты в репозиторий не попали [неизвестно, нужны ли они новой сессии].

## 12. Ограничения и правила

**Нельзя ломать сохранения**
- Не менять существующие `id` карточек, достижений, заданий, жителей и гардероба: они хранятся в сохранениях игроков. Новые - только в конец списков (см. шапку `js/config.js`).
- Не менять `CONFIG.saveKey` и формат сохранения без перевода старых сохранений. `Econ.load` принимает только поля из `fresh()` с тем же типом, поэтому новое поле нужно добавлять в `fresh()`.

**Нельзя ломать базу**
- Не переименовывать SQL-функции, которые вызывает клиент, и не менять их аргументы без новой версии клиента. В игре старая версия держится до перезагрузки.
- Не трогать модель uid: `players.tg_id` - это uid, у ВК без связки он отрицательный.

**Секреты и доступ**
- Никогда не просить и не принимать от пользователя: service_role или secret-ключ Supabase, токен бота, защищённый и сервисный ключи ВК. Пользователь вставляет их в `private_secrets` сам. Пароль базы в репозиторий не класть.
- Publishable-ключ Supabase можно держать в коде.

**Платформы и оформление**
- Не добавлять код под десктоп.
- Не ломать порядок `<script>` в `index.html`. Ранний `VKWebAppInit` в `<head>` должен оставаться первым, иначе во ВК игра снова повиснет на заставке.
- Не удалять скрытый вход в админку - 5 нажатий на строку версии, только для команды. Одно нажатие на эту строку открывает «Что нового».
- Дизайн игры - игровой, дизайн админки - технологичный, их не смешивать.

**Согласовывать с пользователем**
- крупные решения (APK игры, монетизация, баланс);
- удаление функций;
- любые действия, которые требуют от него ручных шагов в Supabase, ВК или BotFather.
